# 备份、恢复与维护

## 备份

`FOLIO_DATA` 保存全部服务端资产。不要在运行时只复制 `.sqlite` 文件而忽略 WAL。

对可直接访问的数据目录运行：

```bash
python3 scripts/backup.py /path/to/data /path/to/new-backup-directory
```

脚本使用 SQLite Online Backup API，校验快照完整性，再复制快照引用的不可变 blob。备份不保留登录会话；目标必须是不存在的新目录。备份期间不得运行垃圾回收。备份失败的目标目录视为不完整，应删除或改名后重新备份。

容器数据位于 `folio-data` 命名卷。可将脚本复制到有 Python 的运维环境执行，也可以先停止 Folio，再完整备份该卷。小型库也可在设置中导出 ZIP：它包含 `files/` 路径树和 `folio-comments.json`，但不包含数据库配置或会话。ZIP 用于迁移/取回原文件，数据库备份用于完整恢复。

## 恢复

1. 停止 Folio，保留旧数据目录的完整副本。
2. 将备份中的 `folio.sqlite` 与 `blobs/` 一起放到新的空目录；不混入旧 WAL/SHM 文件。
3. 对 Docker 数据设置所有权 `10001:10001`，挂载回 `/data`。
4. 启动后使用访问密码登录，核对知识库/文件数、抽查四类文件与批注。
5. 浏览器内清除文件缓存并重新读取，避免本地旧内容干扰恢复核验。

## 回收旧 blob

文件替换、删除不会即时删除物理 blob。这允许导出及在线备份在并发更新期间继续使用旧快照。需要定期维护磁盘：

```bash
# 停止服务，并确认没有备份任务运行。
python3 scripts/gc.py /path/to/data
# 检查输出后执行：
python3 scripts/gc.py /path/to/data --apply
```

默认只打印待删除项。引用中的 blob 不会被清理。导出失败或进程崩溃可能遗留 `export-*.zip`，停机后可删除这些临时导出文件。

## 密码和会话

更改环境中的 `FOLIO_PASSWORD` 后重启会改变后续登录密码。要同时撤销全部已有会话，停机时对数据库执行 `DELETE FROM sessions;`，再启动服务。不要把 `.env`、数据库、日志中的私人路径或备份提交到公共仓库。

## 容量和访问

- 单文件 64 MiB，文本文件 8 MiB；整库导出会临时占用接近库原始大小的额外磁盘空间。
- 前端缓存上限 200 MiB，按插入顺序回收较旧文件。该限制不包含阅读器资源。
- 浏览器只保留本机草稿；切换设备之前需要联网同步。
- 对外访问使用 HTTPS。原型适合个人访问；服务器防火墙仅开放反向代理所需端口。
- 可用 `GET /healthz` 进行进程存活检测。它不代替数据库、磁盘空间和备份监控。
